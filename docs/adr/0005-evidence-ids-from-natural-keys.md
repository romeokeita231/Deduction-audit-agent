# 证据 ID 由自然键派生，引用是封闭集

Status: accepted

`evidence_id` 形如 `<TYPE>:<natural key>`——`POD:SHP-0442`、`BOL:SHP-0442`、`PROMO:PA-07·§3.2`、`SETTLE:PA-07`。要求重新切块、重新嵌入、重新生成数据之后同一份证据的 ID 不变，因此**不能用切块序号编址**：`clause-3` 会随 chunk 策略漂移，而 oracle 里的标注不会跟着变。条款一律用协议编号 + 条款编号作锚点。

文书里的引用拆成两个封闭集字段：

- `references[]` —— 标的物：这笔 Deduction、它的 812 记录。进封闭集校验，**不进指标**。
- `supportingEvidence[]` —— 支持结论的证据。**指标 2 只算这个**。

两者都只能取本次运行工具返回过的 ID；`references` 额外允许这笔扣款自己的 812。

## Considered Options

- **单一 `citedEvidence[]`**：实现最简单，但 812 永远不属于支持性证据，把它算进精确率会让如实引用扣款依据的文书被扣分。指标不该惩罚诚实。

## Consequences

- 合成促销协议必须产出**带显式编号的条款**，不能是自由段落——否则没有稳定锚点，这一条会把 M3 的生成器工作从"写几段话"变成"设计一份文档结构"。
- 封闭集把"编造证据编号"变成确定性失败，指标 2 因此无法被散文润色污染。
- 812 在 prompt 里、不在工具返回里，只能进 `references` 的允许集；漏了的话，文书引用自己的扣款依据会被判失败。**这是最容易踩的一个坑。**
