# 轨迹是旁路，不承担正确性

Status: accepted

业务事实——Verdict、状态转移、文书——只写 PostgreSQL；Agent 轨迹写 MongoDB，写入失败只在扣款上记一个缺口标记，不阻塞、不回滚业务。反过来做的代价不可接受：Mongo 抖一下，一笔已经算完的扣款要回到 `PARKED` 重跑，而轨迹对这个系统的业务价值是复盘与演示，不是正确性。

## Consequences

- 详情页必须能显示"轨迹不完整"，而不是转圈或报错。
- **审计以 PG 的状态转移历史为准，不以轨迹为准。** 有 trace 是加分，没 trace 不影响任何业务结论。
- 被追问"两个库没有分布式事务怎么办"时，标准答案是"其中一个库不承担正确性"，而不是"我们尽量保证一致"。后者听起来像道歉，前者是设计。
